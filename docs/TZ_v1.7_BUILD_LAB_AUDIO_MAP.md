Скриншоты зафиксированы в папке `docs/tz_v1_7/screenshots/`:
- `screen_1_empty.png` — Эталонное начальное состояние сетки слотов (пустые слоты, ровные 3 колонки).
- `screen_2_one_item.png` — Добавление 1-го предмета распирает трек, сжимая соседний слот.
- `screen_3_two_items.png` — Добавление 2-го предмета раздувает карточку «Оружие» и сжимает колонки «Живучесть» и «Дух».
- `screen_4_grid_break.png` — Критический развал сетки: колонка «Дух» вываливается вниз, блок статов перекрывает верстку.
- `screen_5_catalog_scroll.png` — Проблема эргономики: при скролле каталога слоты билда исчезают, статус экипировки не отображается.

### Детальный разбор проблем:
1. **Скриншот 1 (Эталонная геометрия):**
   - 3 категории («Оружие», «Живучесть», «Дух»), каждая содержит сетку 2x6 (12 слотов). Все 3 карточки категорий имеют равную ширину 33.3%, слоты имеют равные пропорции 50/50.
2. **Скриншот 2 (Первичная деформация трека):**
   - При добавлении первого предмета в «Оружие» левый слот получает контент (`.slot-main`, название предмета, стоимость `§ 800`, крестик `✕`).
   - Из-за `repeat(2, 1fr)` без `minmax(0, 1fr)` первый столбец растягивается по `min-content`, сжимая соседний слот `— пусто —` в узкую полоску.
3. **Скриншот 3 (Раздувание карточки категории):**
   - При добавлении второго предмета в первую строку оба слота требуют по ~180-200px.
   - Сетка `.slot-groups` с `grid-template-columns: repeat(3, 1fr)` не имеет ограничения `minmax(0, 1fr)`. Карточка «Оружие» раздувается до ~50% ширины контейнера, насильственно сжимая соседние категории «Живучесть» и «Дух».
4. **Скриншот 4 (Катастрофический развал сетки):**
   - Когда предметы добавлены и в «Оружие», и в «Живучесть», колонка «Дух» не помещается в строку и выталкивается вниз. Панель «Статы билда» перекрывает элементы или разрывает поток.
5. **Скриншот 5 (Эргономический разрыв UX):**
   - Каталог предметов расположен ниже слотов. При скролле вниз пользователь полностью теряет из вида текущий билд, не видит количество свободных слотов и не получает обратной связи о том, добавился ли предмет.
   - В самом каталоге отсутствует индикация того, что предмет уже экипирован.

### 🧩 Subagent 1: UI & Layout Engineering
**Скиллы:** `/ui-design-system`, `/ui-ux-designer`, `frontend-developer`

#### Задача 1.1: Жесткая фиксация сетки слотов билда
* **Причина бага:** Использование `repeat(3, 1fr)` и `repeat(2, 1fr)` по умолчанию использует `minmax(auto, 1fr)`. Длинные строки без `min-width: 0` распирают грид-треки.
* **Требования к верстке:**
  ```css
  /* 1. Главный контейнер 3-х категорий */
  .slot-groups {
    display: grid;
    grid-template-columns: repeat(3, minmax(0, 1fr)) !important;
    gap: 14px;
    width: 100%;
  }

  /* 2. Карточка категории */
  .slot-group-card {
    min-width: 0;
    overflow: hidden;
  }

  /* 3. Сетка 2x6 внутри каждой категории */
  .slot-grid-2x6 {
    display: grid;
    grid-template-columns: repeat(2, minmax(0, 1fr)) !important;
    gap: 6px;
    width: 100%;
  }

  /* 4. Сам слот */
  .slot {
    min-width: 0;
    width: 100%;
    box-sizing: border-box;
    overflow: hidden;
  }

  /* 5. Контейнер иконки и лейбла */
  .slot-main {
    flex: 1 1 0;
    min-width: 0;
    display: flex;
    align-items: center;
    gap: 6px;
    overflow: hidden;
  }

  /* 6. Обрезка текста названия */
  .slot-label {
    flex: 1;
    min-width: 0;
    overflow: hidden;
    text-overflow: ellipsis;
    white-space: nowrap;
    font-size: 11.5px;
  }

  /* 7. Защита от сжатия цены и крестика */
  .slot-cost, .s-clear {
    flex-shrink: 0;
    white-space: nowrap;
  }
  ```

#### Задача 1.2: Закрепление (Sticky) секции слотов при скролле каталога
* **UX-паттерн:** При прокрутке каталога предметов блок билда фиксируется сверху окна, оставаясь всегда видимым.
* **Реализация:**
  - Разделить `.lab-layout` на логические зоны с плавающей фиксацией:
    - Контейнер доски билда `.panel-build-board` получает `position: sticky; top: 0px; z-index: 30; backdrop-filter: blur(12px); background: rgba(14, 18, 26, 0.92); border-bottom: 1px solid var(--border-subtle);`.
    - Добавить компактный режим (при необходимости) или ограничить максимальную высоту каталога скроллом внутри его собственного контейнера (`overflow-y: auto; max-height: calc(100vh - 380px);`).
    - Статы билда (`aside.lab-side`) остаются синхронно привязаны к экрану через `position: sticky; top: 0px;`.

#### Задача 1.3: Визуальное отображение экипированного предмета в каталоге
* **Логика:**
  - В `web/js/ui.js` функция `renderCatalog` принимает текущий набор экипированных ID (`equippedIds = new Set(...)`).
  - Карточке предмета присваивается класс `.is-equipped`.
  - В верстку карточки добавляется метка статуса:
    ```html
    <div class="item-card-equipped-badge">✓ В БИЛДЕ</div>
    ```
  - В стилях `.item-card.is-equipped`:
    - Рамка: янтарный/изумрудный акцент (`border-color: var(--amber);`).
    - Мягкое свечение и плашка статуса в правом верхнем углу карточки.
    - При добавлении или удалении предмета из слота список карточек в каталоге обновляет свой статус мгновенно без сброса позиции скролла.

#### Задача 2.2: Звуковой движок покупки (Zero-Overlap Instant Retrigger)
* **Поведение:**
  - При клике на предмет в каталоге проигрывается звук покупки.
  - **Критическое условие:** При быстрых последовательных кликах звук не должен наслаиваться (полифоническая каша недопустима!). Вместо создания нового `Audio` звук мгновенно сбрасывается в начало и проигрывается снова:
    ```javascript
    // audio.js
    class SoundEngine {
      constructor() {
        this.buyAudio = new Audio('./assets/sounds/buy_sound.mp3');
        this.volume = parseFloat(localStorage.getItem('df_volume') ?? '0.5');
        this.muted = localStorage.getItem('df_muted') === 'true';
        this.updateAudioSettings();
      }

      playBuySound() {
        if (this.muted || this.volume <= 0) return;
        this.buyAudio.currentTime = 0;
        this.buyAudio.play().catch(() => {});
      }

      setVolume(val) {
        this.volume = Math.max(0, Math.min(1, val));
        localStorage.setItem('df_volume', this.volume);
        this.updateAudioSettings();
      }

      toggleMute() {
        this.muted = !this.muted;
        localStorage.setItem('df_muted', this.muted);
        this.updateAudioSettings();
        return this.muted;
      }

      updateAudioSettings() {
        this.buyAudio.volume = this.muted ? 0 : this.volume;
      }
    }
    export const soundEngine = new SoundEngine();
    ```

#### Задача 3.2: Масштабирование до адекватных размеров
* **Проблема:** Сейчас изображение занимает 100% ширины, раздуваясь на 1920px+ и требуя бесконечной вертикальной прокрутки.
* **Решение:**
  - Ограничить размеры интерактивного канваса карты:
    ```css
    .map-panel {
      max-width: 960px;
      margin: 0 auto;
    }

    .map-canvas {
      width: 100%;
      max-height: 68vh;
      display: flex;
      justify-content: center;
      align-items: center;
      background: #090c12;
      border: 1px solid var(--border-subtle);
      border-radius: 12px;
      overflow: hidden;
      position: relative;
    }

    .map-canvas img {
      width: 100%;
      height: auto;
      max-height: 68vh;
      object-fit: contain;
      display: block;
    }
    ```
* **Сохранение интерактивности маркеров:**
  - Поскольку маркеры позиционируются через процентные координаты (`left: x%`, `top: y%`), контейнер `.map-canvas` должен строго сохранять соотношение сторон реального изображения, чтобы маркеры кемпов, урны и мидбосса попадали точно в соответствующие локации.
