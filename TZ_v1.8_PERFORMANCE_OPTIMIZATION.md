## Архитектурные принципы оптимизации
1. **Zero Degradation:** Никаких визуальных ухудшений, занижения качества ассетов или удаления фич.
2. **Native Over Bloat:** Использование нативных возможностей платформ (FastAPI ETag/HTTP Caching, CSS `content-visibility`, `DocumentFragment`, `Path2D`, SQLite PRAGMA) без внедрения тяжелых зависимостей.
3. **Strict Separation of Concerns:** Четкое распределение зон ответственности по 4 специализированным субагентам.

## Команда субагентов и распределение задач

### Субагент 1: Senior Backend Engineer (`agent-backend-perf`)
**Фокус:** FastAPI HTTP Caching, сериализация каталога, SQLite PRAGMA & оптимизация запросов.
**Задачи:**
1. **HTTP Caching & Headers (`src/deadlockforge/api/app.py`):**
   - Убрать агрессивный `no-cache, no-store` для статических файлов (`/assets/...`, `/css/...`, `/js/...`).
   - Для `/assets/...` выставить `Cache-Control: public, max-age=86400, stale-while-revalidate=3600`.
   - Для `/js/...` и `/css/...` реализовать проверку заголовков `If-None-Match` (ETag на основе `os.path.getmtime` и размера файла) с отдачей `304 Not Modified`.
2. **Мемоизация сериализации каталога (`app.py`, `dataset.py`):**
   - В эндпоинтах `/api/heroes`, `/api/items` и `/api/map` закэшировать готовые JSON-строки (`Response(content=cached_json, media_type="application/json")`), чтобы исключить Pydantic `model_dump()` и повторную сериализацию на каждый GET-запрос.
3. **SQLite I/O & Indexes (`src/deadlockforge/storage/db.py`):**
   - Включить `PRAGMA synchronous = NORMAL;` и `PRAGMA temp_store = MEMORY;` в методе инициализации соединения с базой данных.
   - Добавить индексы:
     - `CREATE INDEX IF NOT EXISTS idx_builds_hero ON builds(hero_id);`
     - `CREATE INDEX IF NOT EXISTS idx_reviews_created ON match_reviews(created_at DESC);`
     - `CREATE INDEX IF NOT EXISTS idx_api_cache_key ON api_cache(cache_key);`

### Субагент 2: Senior Frontend Developer (`agent-frontend-dom`)
**Фокус:** DOM-виртуализация, пакетный рендеринг, дебаунсинг вычислений билдов.
**Задачи:**
1. **Оптимизация каталога предметов (`web/js/ui.js`):**
   - Перевести `renderCatalog` на пакетную вставку через `DocumentFragment` вместо множественных мутаций контейнера.
   - Добавить в CSS для `.item-card` нативное правило `content-visibility: auto; contain-intrinsic-size: 0 74px;` для пропуска лейаута невидимых карточек каталога.
2. **Дебаунс и батчинг пересчета билдов (`web/js/app.js`, `web/js/calc.js`):**
   - Обернуть вызовы обновления статов и рендера слотов в `requestAnimationFrame` или микротаску, предотвращая каскадные перерисовки при пакетном заполнении слотов или смене героя.
3. **Кэширование справочников на клиенте (`web/js/app.js`, `web/js/api.js`):**
   - При первом успешном получении `/api/heroes` и `/api/items` сохранять их в `sessionStorage`.
   - При старте `boot()` сначала моментально инициализировать UI из кэша (0 мс), затем в фоне валидировать актуальность через ETag.

### Субагент 3: UI/UX & Graphics Engineer (`agent-canvas-media`)
**Фокус:** Canvas 2D Rendering, оптимизация загрузки видео/аудио и иконок.
**Задачи:**
1. **Двухуровневый Canvas в «Deep Match» (`web/js/deep_match.js`):**
   - Выделить статичный фон графика (сетка, минутные засечки, нулевая линия) в кэшируемый `OffscreenCanvas` или отрисовывать один раз, копируя через `drawImage`.
   - Оптимизировать перерисовку кривой душ: использовать `Path2D` для траектории нетворса, чтобы при движении мыши (hover по маркерам событий) не пересчитывать кривую Безье заново.
2. **Ленивая загрузка тяжелых медиа (`web/index.html`, `web/js/audio.js`):**
   - Заменить `preload="auto"` у фонового видео и музыки на `preload="metadata"`.
   - Инициализировать фоновое видео только после завершения основного `boot()` через `requestIdleCallback` или задержку, отдавая приоритет первому рендеру интерфейса.
3. **Оптимизация загрузки иконок (`web/js/ui.js`):**
   - Оптимизировать каскадный fallback иконок `itemIconNode`, исключив множественные запросы 404. Если формат иконки известен из данных (например, `.webp`), сразу использовать его, а fallback-букву ставить сразу при первой ошибке без проверки промежуточных расширений.
